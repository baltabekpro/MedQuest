# 🎓 MedQuest: объяснение проекта для защиты (без сложного кода)

## 1) Как объяснить проект преподавателю за 1 минуту

**MedQuest** — это CRM-система для медицинского центра.  
Сотрудники клиники в ней:
- регистрируют пациентов;
- создают запросы (жалобы/обращения);
- назначают врача;
- отслеживают статус запроса;
- ведут историю изменений (аудит);
- используют расписание, чат и AI-маршрутизатор.

Система состоит из двух частей:
- **Frontend (React + TypeScript)** — то, что видит пользователь в браузере;
- **Backend (FastAPI + Python)** — API и бизнес-логика;
- **База данных (SQLite)** — хранит пользователей, пациентов, запросы и логи.

---

## 2) Архитектура простыми словами

Поток работы:
1. Пользователь нажимает кнопку на сайте.
2. Frontend отправляет запрос на backend (HTTP API).
3. Backend проверяет права и обрабатывает логику.
4. Backend читает/пишет данные в БД.
5. Frontend получает ответ и обновляет экран.

Схема:
`Пользователь → React UI → FastAPI API → SQLite → ответ обратно в UI`

---

## 3) Ключевые файлы (чтобы показать, что вы понимаете проект)

### Frontend
- `frontend/src/router.tsx` — маршруты страниц и защита доступа (private/admin routes).
- `frontend/src/store/authStore.ts` — хранение токенов и данных пользователя.
- `frontend/src/api/client.ts` — общий HTTP-клиент (Axios), автоматическое обновление access token.
- `frontend/src/pages/*` — сами страницы (Login, Dashboard, Patients, Requests и т.д.).

### Backend
- `backend/app/main.py` — точка входа API, подключение всех роутеров.
- `backend/app/routers/auth.py` — логин, refresh, Google OAuth, 2FA.
- `backend/app/routers/patients.py` — CRUD пациентов.
- `backend/app/routers/requests.py` — CRUD запросов, статусы, комментарии, назначение врача.
- `backend/app/routers/users.py` — управление пользователями и аватарами.
- `backend/app/routers/dashboard.py` — статистика для дашборда.
- `backend/app/routers/chat.py` — чат (REST + WebSocket).
- `backend/app/routers/schedule.py` — расписание приемов.
- `backend/app/routers/classifier.py` — AI-маршрутизация жалобы к специалисту.
- `backend/app/database.py` — подключение к БД.
- `backend/app/models/*.py` — структуры таблиц.

## 4) Примеры кода и как их объяснять

## Пример 1: Защита приватных страниц (frontend)

Файл: `frontend/src/router.tsx`

```tsx
function PrivateRoute() {
  const { accessToken } = useAuthStore()
  return accessToken ? <Outlet /> : <Navigate to='/login' />
}
```

**Как объяснить:**  
Если у пользователя есть токен — он проходит дальше.  
Если токена нет — его отправляют на страницу входа.

---

## Пример 2: Подключение токена к каждому API-запросу

Файл: `frontend/src/api/client.ts`

```ts
api.interceptors.request.use((config) => {
  const token = useAuthStore.getState().accessToken
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})
```

**Как объяснить:**  
Frontend автоматически добавляет `Bearer token` в заголовки, чтобы backend понимал, кто делает запрос.

---

## Пример 3: Роутер backend (подключение модулей)

Файл: `backend/app/main.py`

```py
app.include_router(auth.router)
app.include_router(users.router)
app.include_router(patients.router)
app.include_router(requests.router)
app.include_router(dashboard.router)
```

**Как объяснить:**  
Каждый `router` — это отдельный функциональный блок API.  
Так проект легче поддерживать: авторизация отдельно, пациенты отдельно и т.д.

---

## Пример 4: Создание пациента и запись в аудит

Файл: `backend/app/routers/patients.py`

```py
patient = Patient(**payload.model_dump(), created_by_id=current_user.id)
db.add(patient)
db.commit()
db.refresh(patient)
```

**Как объяснить:**  
Backend берет данные из запроса, создает пациента в БД и возвращает готовую запись с ID.

После этого вызывается `create_audit_log(...)`, чтобы сохранить, кто и что сделал.

---

## Пример 5: Ограничение по ролям

Файл: `backend/app/routers/users.py`

```py
current_user: User = Depends(require_roles("admin"))
```

**Как объяснить:**  
Этот endpoint может вызвать только администратор.  
Если роль не подходит — backend вернет ошибку доступа.

## 5) Основные функции сайта (что показать на демо)

1. **Авторизация**
   - обычный логин/пароль;
   - вход через Google;
   - двухфакторная проверка (2FA);
   - обновление токена через refresh.

2. **Панель Dashboard**
   - количество пациентов;
   - количество заявок по статусам;
   - график активности;
   - быстрые действия по ролям.

3. **Пациенты**
   - добавление, редактирование, удаление;
   - поиск по ФИО, телефону, email.

4. **Запросы пациентов**
   - создание и редактирование;
   - фильтрация по статусу, врачу, приоритету, датам;
   - назначение врача;
   - комментарии к запросу;
   - экспорт в CSV.

5. **Пользователи**
   - создание и редактирование учетных записей;
   - сброс/генерация пароля;
   - загрузка аватара.

6. **Аудит**
   - фиксирует, кто, когда и что изменил.

7. **Уведомления**
   - показывают новые важные события по роли пользователя.

8. **AI-маршрутизатор**
   - по тексту жалобы предлагает нужного специалиста.

9. **Расписание**
   - создание и изменение приемов;
   - проверка пересечений по времени.

10. **Чат**
   - обмен сообщениями между сотрудниками;
   - real-time через WebSocket.

---

## 6) Роли в системе (RBAC)

- **admin**  
  Полный доступ: пользователи, аудит, все данные.

- **registrar**  
  Работа с пациентами и запросами.

- **doctor**  
  Работа с запросами, расписанием, чатом, ограниченный доступ к пользователям.

---

## 7) Как проходит типовой сценарий в системе

Пример:
1. Регистратор добавляет пациента.
2. Создает запрос (жалобу).
3. Назначает врача.
4. Врач меняет статус на `in_progress`.
5. После завершения — `closed`.
6. Все действия попадают в аудит и уведомления.

## 8) Что сказать про безопасность

- JWT access/refresh токены;
- проверка ролей на backend;
- хеширование паролей;
- 2FA через TOTP;
- хранение истории входов (`/auth/sessions`);
- аудит критичных действий.

## 10) Частые вопросы преподавателя и короткие ответы

**1. Почему выбрали FastAPI?**  
Быстрая разработка REST API, типизация через Pydantic, удобная Swagger-документация.

**2. Зачем React + TypeScript?**  
Компонентный UI, строгая типизация и безопасная работа с API-моделями.

**3. Как контролируется доступ?**  
Через JWT + проверку ролей на backend (`require_roles(...)`).

**4. Где хранится история изменений?**  
В таблице аудита; записи создаются при ключевых действиях.

**5. Как работает чат в реальном времени?**  
Через WebSocket endpoint `/ws/chat/{token}`.
